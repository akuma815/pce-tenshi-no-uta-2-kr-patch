# 2026-10-22 제보 2건 분석·수정 인계 (v1.0 → b65)

## 1번: 보스 스프라이트가 창을 덮음

제보 스테이트(마리우스 데몬 전) → 전투 → 리아나 차례에 II → 마법 목록: 한글판·원본(RAM 되돌린 변환 스테이트 + 원본 BIOS) 모두 보스의 수염이 마법 창 위에 똑같이 겹침(`work/shots/kr_31_magic.png`, `orig_31_magic.png`). 스프라이트 우선순위는 원본 설계. 손대지 않음.

## 2번: 카지노 검은 화면 — 원인

원본 디스크 + 원본 BIOS 에서는 「よーし、行くわよ！」 뒤 카드 게임 설명 말풍선이 정상으로 나온다. 한글판은 「좋아、 간다！」 직후 검은 화면(가끔 정상 = 타이밍 경합).

이분 탐색: 모듈·타일 영역 원본화(실패) → 원본 디스크+한글 카드(정상) → 한글 디스크+한글 카드+**엔진 RAM 원본화(정상, 재현성 있음)** → CDRAM 되돌림 37구간 묶음 시험 → **벡터 $4036 의 2바이트(TRAMP $66DF → 원래 $4284)만 되돌려도 정상**. 즉 디스패처 훅은 직접 원인이 아니라 대화 종료→모듈 적재 **타이밍**을 바꾼다.

1프레임 단위 스테이트 비교(`scratchpad stepper.py`)로 확정한 기전:
1. 모듈 적재는 엔진 $8B56 이 워크 RAM $2300 에 복사한 루틴이 `SEI → JSR $E009 → JMP $4000` 으로 수행(슬라이스 $66FC 경유 아님).
2. 카드 모듈(ISO 0xBD5000) 초기화 $5000: `… $5029 STZ $F3`($F3 = 모듈의 VDC CR 섀도) … `$8FD9 CLI`. 모듈 VBlank 핸들러($5093→$50C8)는 CR 하위 바이트에 `$F3 & $26ED` 를 쓴다.
3. SEI 구간에 VBlank IRQ 가 걸려 있으면 CLI 직후 핸들러가 먼저 돌아 CR=$00 → VBlank IRQ 가 꺼져 이후 vsync 대기($52EB, zp $38)가 영원히 끝나지 않는다. 정상 경로는 초기화 중 $F3 에 $08 이 들어간 뒤 첫 VBlank → CR=$0800.
4. 한글판은 타이밍이 이 창에 걸린다(G1 정상 타임라인: 29프레임 CR=0800 / 한글판: 30프레임 CR=0000, 이후 BIOS VRAM 전송 루프 → 모듈 vsync 대기).

## 수정 b65 (`tools/build_btrack_b65_hook_build.py`)

- 모듈 제자리 2곳: `$5032 JMP $8FD9` → `JMP $4FF0`, `$4FF0`(모듈 머리 FF 패딩 끝 16B): `LDA #$08 / STA $F3 / JMP $8FD9`. CLI 전에 $F3 에 VBlank IRQ 비트를 넣어 핸들러가 일찍 돌아도 CR=$0800 이 되게 한다.
- b64 대비 디스크 차이 = ISO 0xBD5FF0 7B + 0xBD6033 2B 뿐, 카드 동일(5632f388…). 씬 770 도박사도 같은 모듈이라 함께 보호.

- 산출물: `build/b65r/`(bin·cue·probes/SystemCard3_btrack_b65.pce·Track02_KR.bin), `build/b65r/dist/Tenshi_no_Uta_II_KR_track02_redump_v1.0.1.xdelta`(원본 Track 02 →), `…_from_v1.0.xdelta`(v1.0 Track 02 →). 둘 다 적용해 SHA-256 61c99c4f… 확인.
