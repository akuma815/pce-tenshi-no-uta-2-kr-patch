# Task 2 — 커스텀 코드 공간 판정

결론: **필드 렌더러 게이트 PASS**. Task 3의 단일 글자 PoC에는 `EF41`만 사용한다.

이 승인은 `renderer.field_main`의 첫 대사 경로에만 적용한다. 메뉴, 전투, 카드, 이름/아이템 및 다른 오버레이 렌더러는 Task 1에서 런타임 범위가 확정되지 않았으므로 승인 대상이 아니다.

## 입력과 범위

- 원본 기준: Task 0에서 잠근 Track02 ISO SHA-256
- 텍스트 분모: `translation/full_extraction/master_text.csv` 18,817행
- 현재 번역: `translation/script_sheet.tsv` 10,155행
- 주의: 전체 추출에는 `needs_review` 17행과 미종결 forensic queue가 있다. 따라서 이 결과는 게임 전체 무누락 선언이 아니다.

## 원본 사용량과 파서 경계

`EB`~`EF`가 선두인 인접 2바이트는 원본 raw의 모든 위치에서 1,509회 발견되며, 후보 풀 중 96쌍이 raw substring과 충돌한다. 그러나 검증된 필드 파서의 문자 경계에서 `EB`~`EF` pair 사용은 0건이고 경계 모델 오류도 0건이다.

필드 디스패처는 ISO `0x4553C`, 런타임 `$853C`에 있다. 명시적인 `0B/0C/0D/0E`, `#`, `%`, `~`, 반각 및 가나 분기 뒤의 일반 2바이트 경로는 다음과 같다.

- `$857F STA $3441`: 첫 바이트 보관
- `$8582 JSR $4033`: 둘째 바이트를 정확히 한 번 fetch
- `$8585 STA $3440`: 둘째 바이트 보관

일반 pair 경로에는 추가 look-ahead가 없다. fetch 소스는 주 스트림 `$53/$54`, 보조 스트림 `$55/$56`, 변수 스트림 `$57/$58`이며 같은 디스패처로 수렴한다. `01` redirect와 `02` continuation은 fetch 계층의 첫 바이트 마커이고 `EF41`은 해당 마커·토큰 범위 밖이다.

원본에서 확인된 단일 제어코드 수는 `0B=53`, `0C=8,179`, `0D=22,092`, `0E=12`, `7E=521`이다.

## 코드 및 글리프 예산

안전 trail은 `40..7E`, `80..FC`로 제한한다. `00`, 제어영역, `7F`, `FD..FF`는 배제한다.

| 항목 | 수량 | 판정 |
|---|---:|---|
| lead 5개 × 안전 trail 188개 | 940 | 의미 경계 기준 전체 후보 |
| 필드 파서 경계 충돌 | 0 | 의미 경계 가용 940 |
| raw substring까지 없는 후보 | 844 | 가장 보수적인 풀 |
| 현재 번역 고유 한글 | 904 | 전역 의미 경계 풀 대비 +36 |
| 한 장면 최대 활성 한글 | 571 | raw-absent 풀 대비 +273 |

전역 고정 매핑은 파서 경계 의미에 의존해야만 904자를 수용한다. 반면 장면/모듈 로컬 재매핑은 가장 보수적인 844쌍 안에서도 최대 활성 집합 571자를 수용한다. 따라서 이후 확장 설계는 **장면 로컬 재매핑 우선**으로 한다.

기존 `translation/char_map.json`은 새 빌드에 사용할 수 없다. 896개 중 안전 trail을 쓰는 항목은 752개뿐이고 144개가 금지 trail을 사용하며, 현재 번역 글리프 8개(`짠`, `쬐`, `찔`, `칙`, `컸`, `튀`, `푼`, `핑`)도 빠져 있다.

## `EF41` 런타임 검증

진단 빌드는 첫 대사 본문의 `6F2D 8141 BCB5 DD`에서 **`6F2D` 두 바이트만 `EF41`로 교체**했다. 제어코드, 종료자, 패딩 및 나머지 본문은 바꾸지 않았다.

BizHawk 화면 관찰 결과:

- 첫 페이지에서 `EF41` 위치는 공백으로 보였다. 아직 커스텀 글리프 훅이 없으므로 예상 결과다.
- 뒤의 원본 `8141 BCB5 DD`는 올바른 위치에 문장부호와 `シオン`으로 표시됐다.
- 다음 페이지가 정상적으로 지워지고 원본 두 번째 대사가 정상 표시됐다.
- 필드 그래픽도 정상이며 MPR2..7은 `80 81 82 83 84 00`이었다.

따라서 `renderer.field_main`은 `EF41`을 제어코드나 두 개의 단일 문자로 오해하지 않고 정확히 하나의 일반 2바이트 문자 단위로 소비한다. 디버거 캡처 시점은 PC `$53AF`였고 `EX_GETFNT` 직전 F9/F8을 직접 촬영한 것은 아니다. 이 제한 때문에 본 결과는 글리프 출력 증명이 아니라 **파서 경계·페이지 정렬 증명**으로만 사용한다.

Lua 추적 방식은 Lua가 활성화되면 BIOS 화면을 통과하지 못했으므로 증거 방식에서 제외했다.

승인:

- Task 3에서 `EF41` 하나를 필드 전용 PoC 코드로 사용
- 정확한 2바이트 치환 방식
