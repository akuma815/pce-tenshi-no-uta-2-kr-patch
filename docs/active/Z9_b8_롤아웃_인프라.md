## 1. b8 이 바꾸는 것 (씬 3개는 b7.6 그대로 — 인프라만)

1. **로더 v4**: 카드 씬 테이블 워크를 절대,Y(8bit → 5씬 한계)에서 zp 포인터
   ($00/$01 저장·복원, (zp),Y) 워크로 교체. 씬 상한 = 폰트 꼬리 용량
   2,701B ÷ 44B = **61씬** (32씬 전량 수용 ✓). 로더 212B, 창 여유 71B.
2. **ARMCHK $A780 → $A880, INDEX_CAP 0x780 → 0x880**: 대형 씬 인덱스
   (3842 = 2,069B, 3362 = 1,985B) 수용. 전 씬 인덱스 뱅크 재배치
   (텍스트 용량 합계 불변). 리더 75B 재검산.
3. **트랙 확장 +1024섹터**: V19 실증 변환 재현 — 트랙2 데이터 끝(파일 프레임
   12693)에 00×2MB 삽입, cue 트랙3+ INDEX +1024프레임. 확장 영역(트랙2-상대
   12693..13716)이 앞으로의 씬 풀 배치처. CD-DA 는 BCD 트랙번호 호출이라
   구조 안전(§6 Z9 실측 — 게이트에서 BGM 확인으로 마감).

정적 검증(verify_btrack_b8.py) 전 항목 PASS: 확장 구조(삽입 00·꼬리 시프트
바이트 동일·cue 시프트 정확), **3씬 전부 serve 시뮬레이션 바이트 왕복**,
armchk @0x880 배치, 테이블 워크 매치/비매치 시뮬, 카드 diff 선언 범위 한정.

     1. 새 지역 진입(로드 완료) → CDL 창 **File → New** →

     2. 그 지역 콘텐츠 플레이 (대사·NPC·**메뉴/장비창**·전투·건물 출입)
     3. 지역을 떠나기 **직전 File → Save 한 번** (전환 로드가 로그에 섞이면
        90%+ 오염으로 그 씬만 자동 기각 — 다시 캡처하면 됨, 다른 피해 없음)
   - 인게임 세이브는 이관됨: b8 SaveRAM → 원본 게임명 SaveRAM 복사

   신규 캡처 등록 → 씬 후보 뱅크 산출 (전역 배제 8뱅크 ∩ CDL cold).
