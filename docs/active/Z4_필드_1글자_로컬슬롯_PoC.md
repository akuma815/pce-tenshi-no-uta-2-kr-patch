# Z4 — 필드 1글자 로컬 슬롯 PoC

상태: **RUNTIME PASS**  
확정일: 2026-07-19

## 최종 구조

필드 엔진 LBA 258/20의 원본 루틴 `$966A..$9697`은 문자 코드 `$8754`와 `$8755`를
별도로 판별하고, `$9172`부터 시작하는 두 개의 32바이트 로컬 글리프 레코드를 복사한다.
Z4 v3는 새 실행 훅을 추가하지 않고 첫 번째 `$8754` 슬롯만 Galmuri8x8의 `가`로
교체했다. 시작 장면 LBA 482/96의 첫 표본 문자는 `$6F2D`에서 `$8754`로 바꿨다.

| 소유 모듈 | module offset | runtime | 변경 |
|---|---:|---:|---|
| `field.main_engine` | `0x5172` | `$9172` | 기존 `$8754` 32바이트 글리프 → `가` |
| `scene.field_start` | `0x1A9F2` | 장면 데이터 | `$6F2D` → `$8754` |

실제 diff는 글리프 18바이트와 문자 코드 2바이트, 총 20바이트다. 원본 실행 코드,
GETFNT callsite, BIOS, MPR, Work RAM, loader table, sector 수와 audio track은 바뀌지 않는다.

## 실패본에서 얻은 규칙

- v1: MPR6/bank `$84`의 `$C737`에서 명령을 실행하면 Memo 진입이 실패한다.
- v2: 반복 `00`/`FF`는 빈 cave의 증거가 아니다. `$9187`은 원본 로컬 글리프 데이터였다.
- v3: 원본 renderer가 소유한 명시적 슬롯과 원본 ABI를 재사용해야 한다.

## 승인 범위와 다음 제한

승인 범위는 field family의 기존 `$8754` 한 슬롯뿐이다. `$8755`까지 사용하면 최대 두
글자 표본은 가능하지만, 전체 번역용 글리프 수로 일반화할 수 없다. 이후 Z5 trace에서
전투도 같은 상주 renderer를 사용한다는 사실이 확인됐으므로, renderer 복제 대신 두 번째
원본 로컬 슬롯 `$8755/$9192`를 battle 전용으로 분리한다.
