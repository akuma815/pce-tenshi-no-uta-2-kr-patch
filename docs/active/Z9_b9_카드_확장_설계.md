## 2. b9 아키텍처 (PoC 통과 시)

- **텍스트**: 전역 유니크 풀 188KB 를 카드 $20+ 에 연속 패킹 (레코드는
  8KB 뱅크 경계 넘지 않게 — serve 는 MPR5 창 $A000-$BFFF 단일 뱅크 read).
- **인덱스**: 씬별 인덱스+armchk 를 카드에 (씬당 카드 뱅크 1개 or 뱅크 내
  오프셋 배치 — armchk 는 $A000 매직 + $A880 고정이라 **씬당 뱅크 1개**가
  코드 무변경. 55씬 = 55뱅크는 과다 → armchk 를 A880 한 곳에 두고 인덱스만
  바꾸려면 인덱스 시작 주소를 데이터화해야 함. 절충: 인덱스 뱅크 하나에
  4씬씩(2KB×4) 못 넣는 이유 = 매직/$A880 고정. **간단안: ROWS 이미지의
  SCRATCH+4 = 씬별 카드 인덱스 뱅크, 뱅크당 [매직+인덱스(≤0x880)+armchk]
  1씬** — 55뱅크 × 8KB = 440KB 는 과다하므로, 인덱스 2씬/뱅크(0x880×2 +
  armchk 사본, armchk 가 $A880 을 두 씬이 공유하려면 인덱스가 0..0x880 —
  두 번째 씬 인덱스는 $A9xx+ 에 두고 매직 검사·버킷 포인터가 절대주소라
  가능, 단 armchk 의 $A000 매직 검사와 SCRATCH+4 만으로는 같은 뱅크 내 두
  씬 구분 불가 → **씬당 1뱅크가 코드-무변경으로 가장 단순**. 뱅크 수 =
  55 ≤ $20..$3F(32뱅크) 초과! → 카드를 768KB($20-$5F, 64뱅크)로 확장하거나
  인덱스 압축 설계 필요 — **설계 결정 지점**, 아래 §3).
- **로더 v5**: 비매치 경로의 복원/PRESENT=0 제거(RAM 풀 부재 — 서브 로드가
  한글을 끄지 않게 됨). 매치 = SCRATCH 복사(인덱스 뱅크 갱신)+PRESENT=1 만.
  ROWS 이미지 = [FF,x,x,x,IBANK,FF,...] (RUN 무동작, SCRATCH+4=IBANK).
- **디스크**: 풀 섹터 불필요 — 9178+ 풀·트랙 확장 사용처가 사라짐(확장
  자체는 유지해도 무해, 제거하면 cue 원복). 엔진 패치(벡터/뱅크81/창)만 유지.
- **폐지되는 것**: 씬별 뱅크 선정·play-CDL·init-coverage·복원 행·extent
  규칙·prefer_card 공유 로직(전역 풀이 이미 전부 공유).

3. 482 페이로드(b4)와 b7 페이로드의 인코딩 동일성 확인(전역 풀 합류 시).

## 3.5 설계 결정 확정 (2026-08-28 — PoC PASS 후)

1. **인덱스 배치 = (b) 채택**: armchk 인덱스 base 파라미터화. 엔트리
   이미지 = `[FF,FF,FF,FF,IBANK,IBASE_HI,FF…]` — RUN 은 byte0=FF 로
   무동작, 리더 v2 가 SCRATCH+4(IBANK), armchk_v3 가 SCRATCH+5(IBASE hi)
   를 읽는다. 씬 인덱스는 256B 정렬로 인덱스 뱅크에 다씬 패킹.
   **카드 크기 = 768KB (2026-08-28 재확정)**: 54씬 전량 실측이 유니크
   263,135B(2,747레코드) + 인덱스 70,818B(정렬 78,080B) = 확장 44뱅크로
   512KB(32뱅크)를 초과 — §1 의 188KB/45KB 는 33씬 기준 과소치였다.
   **768KB + 최원단 뱅크 $4B read 는 b9poc_768k4B 프로브로 런타임 실증
   완료** (`translation/b9poc768_runtime_2026-08-28/`). 실배치(v3) =
   텍스트 33뱅크($20-$3F,$44) + 인덱스 11뱅크($45-$4F), $40-$43 은
   Arcade 섀도우로 스킵(§3.5-3), 스페어 16뱅크($50-$5F)는 primary
   컨테이너·비주얼씬 자막 트랙 확장분으로 예약.
2. **로더 = v4 그대로 유지 (v5 폐기)**: 행 이미지가 전부 FF 라 RUN 이
   무동작이므로 로더 코드 무변경. 비매치 시 PRESENT=0 도 유지한다 —
   전 씬이 테이블에 있으므로 비매치 = 비씬 로드(primary/비주얼)뿐이고,
   그때 PRESENT=0 은 stale 인덱스 오매치(잘못된 한글 서브)를 막는
   안전판이다 (폴백 = 원문 일본어, b8.3 게이트로 실증된 의미론).
3. **armchk_v3 필수 변경 — SCRATCH_KH $AFFE 는 ROM 에서 불가**: 기존
   armchk 는 인덱스 뱅크 내 $AFFE 에 키 hi 를 STA 하는데 카드는 ROM 이라
   쓰기가 무시된다. → SCRATCH_KH 를 엔진 상태 블록의 빈 바이트 $C8FD 로
   이동 (리더 컨텍스트는 MPR6=$84 보장, state=0 패치 범위 $C8F9-FE 에 포함).
   그 외 변경 = 매직/버킷 ptr 접근을 (SCRATCH+5)<<8 base 의 zp 간접으로.
   **armchk 코드 위치**: 기본 카드 $1F 폰트 꼬리(파일 0x3FA00, 논리
   $7A00) 단일 사본, 리더 v3m 이 MPR3=$1F 브래킷(JSR $7A00, MPR5=인덱스
   뱅크는 데이터용 유지)으로 호출. 인덱스 뱅크의 $0880 홀은 FF 예약.
   **⚠ 확장 뱅크 $40-$43 사용 금지 (2026-08-28 v1/v2 FAIL 재진단으로
   확정)**: 물리 뱅크 $40-$43 은 **Arcade Card RAM 창이 카드 ROM 을
   가린다** (진단 lua "System Bus (21 bit)" 실측 — phys 0x84000=0000,
   카드 파일은 42B4). v1 행업 = $42 fetch 가 00(BRK), v2 무장 0건 =
   인덱스 매직 00. 최초의 "확장 뱅크 fetch 불가" 진단은 오귀속. v3 =
   EXT_BANKS 에서 $40-$43 스킵 (텍스트 $20-$3F+$44, 인덱스 $45-$4F,
   스페어 16뱅크).
4. **씬 모집단 실측 정정**: overlay 씬 = 54 (96섹터 32 + 69~94섹터 22,
   `show_scene_lba_pcehawk.lua` 실측 테이블). HANDOFF 구판의 "55씬 분석·
   인코드 전량 완료"는 과장 — 실제 완료 = 33씬(96섹터 32 + 578), 원시
   714,527B/유니크 188,068B 도 그 33씬 기준. **비96섹터 21씬(1058,1538,

## 4. 유의·잔존 사항

- **실기 호환**: 512KB+ 시스템카드는 실기에서 flashcart(EverDrive 계열)
  필요 — 배포 노트에 명시할 것. 에뮬레이터(TurboNyma) 실증은 완료.
  PCEHawk 의 대용량 카드 수용은 미확인(진단용 — 필요 시만).
- **미번역 잔존 triage** (b8.3 게이트에서 관측): 후보 = 미수록 primary
  컨테이너(8개, 예: 642×71)·분석 제외 행·비기본 스트림 경로. 카드 상주
  후에도 남는 것들 — 출하 씬에서 일본어 발견 시 스크린샷 → master 검색.
- menu_memo_system(32,997B)·고정길이 family(~2.9KB)·비주얼씬 자막은 별도
  트랙 그대로 (HANDOFF §1).
- 정리 가능 파생물: b8/b8_2 bin·카드(FAIL/구판), b7_6·b7 (재생성 가능).
  b8_1 은 b8.3 직전 안전판으로 당분간 유지 권장.
