# Z1 — CD 모듈 디렉터리와 로더 그래프

상태: **관측 경로 PASS / 하위 렌더러 진입 PC는 후속 추적 항목**  
기준 원본 SHA-256: `D16D29EB80B1B74A2EC929924349256B50B8F9F5C9A3FA37B6FCC08B059B22C5`

## 결론

천외마경식 재설계의 첫 단계로, 원본 CD를 수정하지 않고 로더 표와 실제 BizHawk
CD_READ 기록을 결합했다. 시작 필드부터 첫 전투, 필드 복귀, 탑 진입까지의 전이는
다음과 같이 확정됐다.

```text
LBA 258/20  field.main_engine (bank 80-84)
    |
    +-- directory entry 2  --> LBA 482/96  시작 필드 패키지 (bank 68-7F)
    |                              |
    |                              +-- Memo: 추가 CD_READ 없음
    |                              +-- 초상화: 추가 CD_READ 없음
    |                              `-- entry 0 --> LBA 290/96 첫 전투 패키지
    |                                                   |
    |                                                   +-- entry 2 --> LBA 482/96 필드 복귀
    |                                                   `-- entry 27 -> LBA 2882/96 탑 진입
    `-- loader code $66DA-$671D, BIOS CD_READ $E009 호출
```

가장 중요한 구조적 사실은 LBA 482, 290, 2882가 모두 `mode=$06`, 시작 bank
`$68`로 96섹터를 읽는다는 점이다. 즉 각 전환은 Super RAM의 `$68-$7F`, 총
192 KiB를 통째로 교체한다. 이 범위에는 장면을 넘어 살아 있어야 하는 공용 훅,
글리프 캐시 또는 상태를 둘 수 없다. 기존 방식이 전투·탑·Memo에서 반복적으로
깨진 직접적인 구조 원인과 일치한다.

## 로더 표와 코드

- 소유 모듈: Track02 `LBA 258`, 20섹터
- 런타임 배치: physical bank `$80-$84`, CPU `$4000-$DFFF`
- 장면 디렉터리: Track02 ISO `0x83531`, 런타임 `$6531`
- 레코드 수: 55
- 레코드 형식: `LBA high, LBA middle, LBA low, sector count`
- 로더 본체: `$66DA-$671D`
- BIOS CD_READ 호출: `$66FC: JSR $E009`
- 복귀 PC: `$66FF`
- 목적 bank: RAM `$22D0`에서 읽으며 관측값은 `$68`

HuC6280 실제 역어셈블 결과의 핵심 부분은 다음과 같다.

```text
66DB  LDA $6531,X   ; LBA high
66DE  STA $FC
66E0  LDA $6532,X   ; LBA middle
66E3  STA $FD
66E5  LDA $6533,X   ; LBA low
66E8  STA $FE
66EA  LDA $6534,X   ; sector count
66ED  STA $F8
66EF  STZ $F9
66F1  LDA #$06
66F3  STA $FF
66F5  LDA $22D0
66F8  STA $FA
66FA  STZ $FB
66FC  JSR $E009
```

## 모듈 분류

| ID | 종류 | LBA/섹터 | 배치 | 판정 |
|---|---|---:|---|---|
| `boot.kernel` | 실행 엔진 | 2/16 | 80-83 | 시작 추적 및 `JMP $600B` |
| `opening.engine` | 실행 엔진 | 98/20 | 별도 초기 배치 | 시작 추적 및 `JMP $5000` |
| `field.main_engine` | 실행 엔진 | 258/20 | 80-84 | 로더 표·필드 GETFNT 소유 |
| `field.resource` | 리소스 | 278/12 | 85-87 추정 | 후속 MPR 관측 |
| `scene.field_start` | 장면 패키지 | 482/96 | 68-7F | 시작 필드 |
| `scene.battle_first` | 장면 패키지 | 290/96 | 68-7F | 첫 전투 전이 |
| `scene.tower_first` | 장면 패키지 | 2882/96 | 68-7F | 첫 탑 전이 |
| `subrenderer.memo` | 상주 하위 렌더러 | 별도 read 없음 | 미확정 | Memo 진입 전후 CD_READ 없음 |
| `subrenderer.portrait` | 상주 하위 렌더러 | 별도 read 없음 | LBA482 bank 6C 의존 | 초상화 대조 추적 |

96섹터 장면 묶음은 선두 바이트가 서로 같은 패키지 헤더 형태이므로, 실행 진입점이
확인되기 전에는 실행 모듈로 부르지 않는다. `LBA 3330`이 초상화 모듈이라는 과거
가설도 대상 추적에서 해당 read가 전혀 없었으므로 폐기한다.

## 산출물과 재현

- `translation/ziria_module_catalog.json`: 두 디렉터리 55개 전체, 모듈 배치,
  CD_READ 관측 집계, 미확정 항목
- `translation/ziria_loader_graph.json`: 시작·전투·복귀·탑 및 Memo/초상화 전이
- `tools/build_ziria_z1_loader_graph.py`: 원본 해시를 먼저 검사하는 읽기 전용 생성기
- `tools/verify_ziria_z1_loader_graph.py`: 핵심 LBA, bank, 디렉터리 번호와 간선 검증
- `tools/huc6280_disasm_verifier`: `--raw` 모드로 원본 범위 역어셈블 지원

재현 명령:

```powershell
python tools\build_ziria_z1_loader_graph.py
python tools\verify_ziria_z1_loader_graph.py
```

## Z1 게이트 판정

관측된 기준 경로의 모든 CD_READ는 소유 엔진 또는 장면 패키지에 연결됐고, 전투 후
필드 복귀와 전투 후 탑 진입이 동일한 로더 표의 항목 2·0·27로 설명된다. 따라서
Z2 identity rebuild에 필요한 추출 경계와 로더 관계는 확보됐다.

Memo와 초상화는 별도 CD 모듈이 아니라 현재 장면 안에서 호출되는 하위 렌더러로
판정했다. 정확한 진입 PC는 Z2의 무수정 재조립을 막는 조건이 아니며, 해당 family를
실제로 분리하는 단계 전에 별도 실행 추적으로 확정한다.
