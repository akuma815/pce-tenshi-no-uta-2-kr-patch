# Z2 — 무수정 모듈 추출·재조립

상태: **PASS**  
실행일: 2026-07-18

## 목적

번역 코드나 글리프를 추가하기 전에, 천외마경식 모듈 빌드 파이프라인이 원본의
혼합 모드 CD 구조를 손상시키지 않는다는 것을 증명한다. 원본 CUE/BIN은 읽기 전용
입력으로만 사용했으며 결과물은 `module_relink/` 아래에 생성했다.

## 혼합 모드 경계

- 전체 트랙: 34개
- Track 01: raw AUDIO, 2352 bytes/frame
- Track 02: MODE1/2048 cooked data
- Track 02 BIN 시작: `7,914,480`
- Track 02 크기: `19,103,744` bytes
- Track 02 섹터: 9,328 × 2,048 bytes
- Track 03~34: raw AUDIO, 2352 bytes/frame

CUE의 INDEX 01 프레임 차이와 트랙별 sector size로 각 파일 구간을 계산했고, 마지막
트랙 종료가 원본 BIN 크기 `523,184,384`와 정확히 일치함을 확인했다.

## 추출 구조

Track 02는 primary와 overlay 로더 표의 모든 시작·종료 경계 및 Z1 의미 모듈 경계를
합쳐 152개의 비중첩 세그먼트로 분해했다.

- partition segments: 152개
- partition coverage: 19,103,744 bytes, Track 02의 100%
- loader logical modules: 110개
  - primary 55개
  - overlay 55개
- semantic modules: 10개

논리 모듈은 같은 물리 LBA를 가리키거나 서로 겹칠 수 있으므로 분석용 view로 유지한다.
실제 identity 조립에는 빈틈과 중첩이 없는 `segments/`만 사용한다.

## 재조립 방식

1. 152개 세그먼트만 순서대로 결합해 Track 02 ISO를 생성한다.
2. 원본 BIN의 Track 01 raw byte 구간을 그대로 출력한다.
3. 재조립 Track 02를 출력한다.
4. Track 03~34 raw byte 구간을 원본에서 그대로 스트리밍한다.
5. 원본 CUE를 바이트 단위로 그대로 복사한다.

오디오를 WAV로 변환하거나 다시 인코딩하지 않으며 pregap, INDEX, track 위치를
변경하지 않는다.

전체 BIN과 CUE가 암호학적으로 동일하므로 에뮬레이터가 구별할 수 있는 입력 차이는
없다. Z2에서는 별도 런타임 변형 검사가 필요하지 않으며, Z3 이후 최초로 바이트가
달라지는 빌드부터 BizHawk 회귀 테스트를 다시 적용한다.
