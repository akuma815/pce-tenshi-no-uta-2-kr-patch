# Z10 — b10 메뉴/전투/UI/이름 테이블 한글화 (2026-08-28~29)

빌더: `tools/build_btrack_b10_hook_build.py` (= b9 모듈 재실행 + 메뉴 패치)
패치 생성: `tools/build_btrack_b10_menu_inplace.py`
검증: `tools/verify_btrack_b10.py` (b9 검증기 전체 재실행 포함)
산출: `*_btrack_b10.bin/.cue` + `probes/SystemCard3_btrack_b10.pce`
설정: `cfg_b10_play.ini`

## 1. 원리 (전부 런타임 실증)

1. **제자리 SJIS 치환**: 카드 폰트가 한자 슬롯을 한글로 대체하므로, 원문
   레코드를 한글 슬롯 SJIS 로 바꾸면 **어느 렌더러든 훅 없이** 한글이
   나온다. b10poc(로드 화면 'ロード'→'로드' 렌더)로 메뉴 렌더러 실증.
2. **테이블 재패킹 + 포인터 재작성**: 이름류 테이블(캐릭터/마법/몬스터/
   장비/지명/명령)은 **u16 포인터 테이블**이 문자열 앞에 있음을 실측
   (레코드 시작열과 delta 전 엔트리 일치로 발굴, 재정렬 2차 테이블은
   옛-주소 집합 매칭으로 발굴). 문자열을 재패킹하고 포인터를 재작성하면
   개별 길이 제한이 사라진다.
3. **창 아레나**: 같은 8KB 논리 창의 모든 포인터-런 extent + 제자리
   치환으로 생긴 꼬리 여유를 하나의 아레나로 묶고, 프래그먼트별
   subset-sum DP 로 배치 (그리디/best-fit 은 슬리버 분산으로 실패 —
   실측). 창 부족분만 짧춤 오버라이드로 해소.

## 2.5 게이트 1차 피드백 수정 (2026-08-29 — b10 v2)

3. 이 과정에서 마감 짧춤 추가 (~30건 — §3 검토 목록에 합산).

## 2.6 게이트 2차 피드백 수정 (2026-08-29 밤 — b10 v3)

1. **장비창 右 일문**: 右左頭体他 클러스터 ISO 전수 4곳 중 2곳
   (0x46929, 0x87CC8)의 右 가 미인덱스 머리 레코드(직전 코드가
   스트라이드4 즉치 베이스 $9929/$ACC8 로 소비 — 역어셈 확인).
   빌더에 SUPPLEMENT(미인덱스 보충, 원문 바이트 assert) 추가로 제자리
   치환. **사용자 실기 확인 PASS**.
2. **상태창 두 위치 어긋남**: 상태창은 단일 레이아웃 템플릿({~} 간격,
   equip 라벨 인라인). 번역 줄 `민첩　{~}×13두` 의 **전각 스페이스
   0x8140 이 {~}런과 결합해 두를 좌측으로 붕괴**시킴. 진단 경로:
   ① stray 추정 → 0x49DB1 마커 실험 기각, ② 민(8C7E) trail-7E 가설
   → 포크 기각, ③ 8140→{~}{~} 포크(E5)·원문 머리 복원(E7) 모두 정상
   → 원인 확정. 포크 실험 시리즈(E1~EF)로 확립한 **이 레코드 렌더러의
   실증 규칙**: ① {~}=1바이트 1스텝, 8140(전각 스페이스)=2바이트 —
   폭은 바이트 수에 비례하고 민첩 줄은 원문 素早さ 줄보다 스페이싱
   1바이트(반 칸)가 더 필요, ② **8140 은 레코드 내 짝수 오프셋에서만
   정상**(홀수 = 두 붕괴, v2 의 진범), ③ **{~} 연속 런은 ~16 상한**
   (18런 = 라벨 붕괴, EB 실측), ④ **헤더 {~}14 축소 금지**(13/12 모두
   이름 첫 글자(ﾌ) 클리핑, EA/EB 실측), ⑤ 지능(4B)>賢さ(3B) 의 +1B 는
   레코드 안에서 상쇄 불가(전 라인 픽셀 고정) → 씬 사본은 **{#1} 토큰
   제거(-2B)** 로 해소(EF 포크: 이름·5라벨 x187 정렬·창 정상 실증 —
   {#1} 의미는 미규명이라 게이트에서 타 캐릭터/재진입 확인 필요).
   최종 = id 오버라이드 2건: 씬(iso:008AD22) = {#1} 제거 +
   `민첩{~}{~}{~}…{~}두`(16{~}) + `운{~}　{~}×15타`(8140 짝수 유지);
   시스템(iso:004A650, {#1} 없음·소비 컨텍스트 미확인) = 안전형
   `민첩{~}×15두`(두 반 칸 좌측 — 소비처 발견 시 재검토, worklist).
   실험 도구 = `run_b10_poke_*.lua`(스테이트 포크),
   `run_b10_state_forensics.lua`(RAM 덤프), 증거 =
   `translation/b10_status_diag_2026-08-29/`.
3. **NOFIT 재배치 경로 (다음 반복)**: 시스템 창 0x4A520 부근에 창 내
   문자열 전반을 가리키는 **마스터 u16 포인터 테이블** 실재(씬 사본
   0x8ABAE 부근 동형). 메인 메뉴(D58F, +2B)·도구 명령(D738, +1B)·
   メモ(D7D3, +2B)의 단독 포인터 확인 — 재배치+포인터 재작성으로 해소
   가능. 공간 회계: 씬 창은 여유 28B 로 수용 가능, 시스템 창은 아레나
   cap=need 정확 일치라 **5B 확보 필요**(짧춤 1~2건 또는 추가 공간
   발굴 — 인간 결정 항목).

## 2.9 미인덱스 클래스 해소 + 메모 원인 규명 (2026-08-30 — b10 v6)

게이트 3차 피드백 4건 중 **2건 해소, 2건은 동일 근본 원인으로 별도 트랙**.

**해소**

1. **로드 화면 時間/分**: 포맷 문자열 `Ｌ%01d%2d時間%01d分` 는 미인덱스이며
   **ISO 전수 1곳(0x8AFC6)**. 時間(4B)→시간(4B)·分(2B)→분(2B) 로 길이가
   같아 제자리 치환으로 끝(SUPPLEMENT 편입).
2. **파티/상태창 캐릭터명 フェイト**: 1바이트 압축 가나(CC AA B2 C4)로
   저장돼 SJIS 스캔에 안 잡혔다. 미인덱스 사본 2곳(sys 0x499A6,
   scene 0x89ADA)이며 **각 사본의 포인터가 이름 테이블 머리 엔트리**
   (sys 0x49778=C9A6, scene 0x89900=CADA — 다음 엔트리가 +5 인 연속 배열로
   확정). 재패킹 런이 머리 1엔트리를 빼고 시작해 누락됐던 것.
   → `SUPPLEMENT_RELOC` 로 등록해 §2.8 재배치 경로에 태움(5B→7B).
   리아나·시온은 이미 런에 포함돼 한글이었다.
   ⚠ 창 2B 확보를 위해 표기 통일에서 マトック(곡괭이, 대사 37회)를 양보 —
   상시 노출되는 파티창 이름 우선. 통일 잔여 4건(등장 415회).

**별도 트랙 (근본 원인 동일: 메모/초상화 소비 경로가 b9 리더를 안 탄다)**

3. **메모 항목명**(魔物のこと·リアーナのこと): **b9 페이로드에 존재**
   (`reference_kind = MEMO_POINTER_TARGET`, 예: '마물에 대해' 13B)인데
   화면은 일문 → 메모 화면의 읽기 경로가 armchk/serve 를 경유하지 않는다.
   `次の目的のこと` 는 별개로 **번역 자체가 없음**(same_as_original=yes,
   원문에 1바이트 가나 접두 `タあタお…` 가 붙어 있어 번역에서 누락).
4. **메모/초상화 대사**({%f} 접두): 4,083행 / **고유 83개**. 기존 기록의
   "비기본 스트림($53≠0, armchk 의도적 거부)" 와 같은 계열.

→ 다음 트랙 = **메모/초상화 소비 경로 추적**(메모 화면에서 $E009·리더
진입 여부를 PCEHawk 로 관측) 후 서브 경로 확장. 고유 83개뿐이라 경로만
열리면 물량은 작다.

### 미해결 (다음 반복 — 미인덱스 고정 소비 클래스)

- **파티창/상태창의 캐릭터명(フェイト/シオン)**: Z8 인덱스에 없는
  씬 상주 사본(예: 0x0A9B134)과 테이블 머리의 미인덱스 フェイト 레코드

- **로드 화면 時間/分**: 시간 포맷 문자열도 미인덱스 — 동일 클래스.

## 2.7 표기 통일 (2026-08-29 사용자 결정 — b10 v4)

**결정: 대사 쪽 표기로 통일.** 축약(메뉴) 표기가 대사와 어긋나는 37건 중
**대사 등장 상위 9건(등장 합 493회)을 대사 표기로 통일**했고, 나머지 28건
(전부 등장 7회 이하)은 **창 물리 용량 한계로 메뉴 축약 유지**.
결정 기록 = `translation/REVIEW_b10_짧춤_표기통일.tsv` 의 `결정` 열.

- 통일: アレフ→알레프(222회)·ライヒ→라이히(72)·宝箱 메시지(66)·
  天河の滴→은하방울(55)·マトック→곡괭이(37)·エルの魔法水(13)·
  ルミエナ→루미에나(11)·魔氷の鎧→마빙갑옷(9)·ライヒ草→라이히초(8).
- **창 용량이 진짜 한계**: 통일에 sys +72B / scene +90B 가 필요한데
  8KB 논리 창은 하드캡이다(포인터가 u16 창 상대 → 창 밖 배치 불가).
  미참조 00/FF run 은 sys 8B·scene 14B 뿐, 도너 임계 4→3 완화는 15/18B.

### 이번에 넣은 무손실 공간 회수 3종 (빌더)

1. **아레나 dedupe**: 인코딩이 같은 아레나 행은 한 벌만 배치하고 주소 공유
   (포인터가 어차피 재작성되므로 무위험). 29B.
2. **제자리 dedupe**: 같은 인코딩의 제자리 레코드는 대표 1벌만 남기고
   나머지는 **마스터 테이블 포인터를 대표 주소로 돌려** extent 전체 회수.
   안전조건 = 6엔트리+ 연속 u16 테이블에만 참조 + 코드 즉치(LDA #lo/#hi)
   없음, 하나라도 어기면 유지. 8B.
3. **배치 실패 복구**: 조각별 subset-sum 이 잔여를 잘게 남겨 큰 항목이
   좌초 → 창 전체 fail-closed 되는 사고를 막기 위해 ① 잔여 first-fit
   수선 패스 ② 좌초 항목 강제 선배치 재시도(5회) ③ BFD/FFD 대체 전략.

### 폴백 정책 (필수)

`b10_prefer_full.txt` = 대사 표기 우선 목록. 제자리 고정길이에서 전체
표기가 **안 들어가면 짧춤 오버라이드로 폴백**한다 — 폴백 없이 통일만
적용했다가 **NOFIT 167→229(62행이 일문 복귀)** 를 실측했다(§9).

## 2.8 NOFIT 재배치 (2026-08-30 — b10 v5)

**메인 메뉴(魔法/状態/道具/装備/メモ/ロード)·도구 명령(使う/交換/捨てる)·
メモ 제목 등 미번역 잔여를 해소.** NOFIT 167 → **142**(25건 재배치).

원리: 제자리에 안 들어가는 단독 레코드도 **창 마스터 포인터 테이블에
참조가 있으면 아레나로 옮긴다**. extent 가 용량에, 인코딩이 수요에
들어오므로 **순비용 = 초과분(대개 1~2B)뿐**이다.

- **마스터 테이블 판정**: 6엔트리 이상 연속 u16 이 전부 창 논리범위를
  가리키고 그중 3개 이상이 알려진 레코드 시작. 전 엔트리를 요구하면
  미인덱스 문자열에서 배열이 끊겨 채택이 1건에 그친다(실측).
- **안전장치**: 코드 즉치(LDA #lo/#hi) 참조가 있으면 재배치 금지.
  배치가 깨지면 **비싼 것부터 하나씩 빼며 재시도**(전부 포기하면 멀쩡히
  들어갈 행까지 일문으로 남는다 — 씬 창에서 실측).
- **용량 트레이드 (사용자 판단 반영)**: 씬 창에서 메인 메뉴·メモ 를 넣기
  위해 표기 통일 9건 → **5건**으로 축소(양보: 라이히초 8회·마빙갑옷 9회·
  루미에나 11회·엘의마법수 13회). 상시 노출되는 메인 메뉴 한글화가
  저빈도 아이템명 표기 일치보다 우선이라는 판단. 남은 통일 5건 =
  알레프(222회)·라이히(72)·상자 메시지(66)·은하방울(55)·곡괭이(37)
  = 대사 등장 452회분.

**잔여 NOFIT 142행**: 마스터 테이블 참조가 없거나(창 밖 소비) 부족분이
큰 행. 부족 1B 가 80건이라 추가 공간만 확보되면 대부분 해소 가능 —
다음 후보 = 제자리 dedupe 확대, 창별 미사용 run 재조사.

## 2.10 메모 목록 해소 + 초상화 트랙 근거 (2026-08-30 — b10 v7)

### 메모 목록 = b9 서브가 아니라 **씬 패키지 RAM 직접 읽기** (실증)

메모 화면 세이브스테이트(`diag_memo.State`) RAM 덤프에서 원문 바이트가
**뱅크 $7F(phys 0x0FE011~)에 그대로** 있고 ISO `0xA100B` 와 일치.
그 시점 `zp $53 = C0`(비기본 스트림) → armchk_v3 의 첫 게이트
(`LDA $53 / BNE pass`)에 걸려 서브가 거부된다. b9 페이로드에 번역이
있어도(`reference_kind = MEMO_POINTER_TARGET`) 화면에 안 나오는 이유.

→ **해소: b10 이 디스크에서 제자리 치환**. `memo_ptr_ids`(b9 payload 의
MEMO_POINTER_TARGET) + 목록 헤더를 타깃에 편입. 7항목 전부 슬롯 내 적합:

| 원문 | 슬롯 | 한글 | 크기 |
| --- | ---: | --- | ---: |
| (헤더)次の目的のこと | 24B | 다음목표 | 22B |
| リアーナのこと | 8B | 리아나 | 7B |
| ダーク教のこと | 10B | 다크교단 | 9B |
| 魔物のこと | 8B | 마물 | 5B |
| 古代技術のこと | 12B | 고대기술 | 9B |
| 天上界のこと | 10B | 천상계 | 7B |
| 地底界のこと | 10B | 지저계 | 7B |

⚠ `のこと`(~에 대해) 어미를 떨어뜨린 축약 — 목록 문맥상 자연스럽다는
판단이나 **릴리스 전 인간 검토 대상**(§3).

### 인코더/필터 실측 (중요)

- **`{%f}` 뒤 한 글자 = 초상화 번호 파라미터**다. 원본 바이트가
  `25 66 31` 인데 추출기가 0x31 을 'お' 로 디코드한 것. 인코더는 이미
  정확히 복원한다(`{%f}お{#5}리아나` → `2566312335 88B788AD88B4`).
  **b10 의 `has_japanese` 가 이 파라미터를 본문으로 오판해 초상화
  4,083행 전량을 걸러내고 있었다** → `text_only()` 로 분리.
- 메모 헤더의 `タあタお…` 접두는 **제어 바이트 0xC0 열**이다. 원문
  재인코딩 == ISO raw 로 왕복 확인. `_CTRL_PREFIX` 로 일문 검사 제외.
- 오버라이드가 있으면 `same_as_original=yes`(미번역) 행도 구제하도록
  `encoded()` 순서 변경 — 헤더가 이 경로로 살아났다.

### 초상화 대사(83 고유) — 다음 트랙

제자리 적합률 실측: **적합 2 / 초과 54(부족 합 441B, 중앙 7B) /
일문 잔존 27**. 제자리로는 못 넣으므로 **카드 서브를 살리는 쪽이 정답**.

#### 엔진 디스패처 $4284 해독 (2026-08-30, RAM 덤프 실측)

물리 0x100284 = 논리 `$4284` (뱅크 $80 @ MPR2). 스트림 우선순위와
**각 스트림의 포인터 쌍**이 확정됐다:

```
$4284: A5 55      LDA $55
$4286: D0 32      BNE $42BA     ; ① $55 스트림 → 포인터 = zp $54/$55
$4288: A5 53      LDA $53
$428A: D0 1F      BNE $42AB     ; ② $53 스트림 → 포인터 = zp $52/$53  ★메모/초상화
$428C: AD 69 2E   LDA $2E69
$428F: D0 41      BNE $42D2     ; ③ $2E69 스트림 (MPR6 스왑 경로)
$4291: …          ; ④ 기본 → 포인터 = zp $4B/$4C

$42AB: B2 52      LDA ($52)     ; ② 본체: 읽고 $52/$53 증가
$42BA: B2 54      LDA ($54)     ; ① 본체: NUL 이면 STZ $54/$55 후 $4284 재진입
```

즉 **$53 스트림은 zp $52/$53 가 텍스트 포인터**다. armchk_v3 는 키를
`$4C & $1F`(키 상위) + `$4B`(키 하위) + MPR 매핑(`$4C>>5`, `$22D0`)에서
뽑고, 매치되면 원본 포인터 `$4B/$4C` 를 **레코드 길이만큼 전진**시킨 뒤
`FLAG/TBANK/CURL/CURH` 를 채운다(카드 서브 개시).

#### 키 산식 검증 완료 (2026-08-30 — 개조 전 필수 근거)

세이브스테이트 zp 실측으로 **`$53` 스트림이 기본 스트림과 동일한 키 공간을
쓴다**는 것을 확인했다. 따라서 armchk 는 포인터 쌍만 바꾸면 된다.

| 상태 | `$4B/$4C` | `$52/$53` | 역산 소스키 | 해당 레코드 |
| --- | --- | --- | --- | --- |
| 메모 화면 | 00/00 | **31/C0** | keyhi=`$53&1F`=00, keylo=`$52`=31 → `0x10031` | ISO `0xA1031` = ダーク教のこと ✔ |
| 전투 | 00/00 | **10/D5** | keyhi=15, keylo=10 | (초상화 대사 계열) |

`$53` 값(C0·D5)은 armchk 의 범위 검사 `#$80 ≤ A < #$E0` 도 통과한다.
기본 스트림 쪽 `$4B/$4C` 가 00/00 인 것도 정합적(그 시점 비활성).

#### 다음 단계 설계 (b11 후보)

armchk_v3 에 **스트림 선택**을 넣는다: `$53≠0` 이면 키 산출과 전진을
`$52/$53` 로 수행(그 외에는 현행 `$4B/$4C`). zp 가변 주소 접근이 필요하니
자기수정 대신 **경로 복제**(~40B 추가)가 안전하다. `$55≠0` 은 서브 중이므로
무장 금지(현행 코드에 검사가 없다 — 함께 추가할 것).

⚠ 이 변경은 **현재 정상 동작하는 대사 서브 전체에 영향**을 준다.
반드시 b10 v7 게이트 통과 후 **단독 빌드**로 올리고, 회귀 게이트
(첫 대사·전투·상점·메모)를 새로 받을 것.

## 2.11 래퍼 미인덱스 사본 (2026-08-30 게이트 4차 — b10 v8)

**Z8 인덱스에 빠진 사본이 화면을 담당하는 클래스가 또 있다.** 전투
메시지는 씬 패키지에 **`10 <내용> 0F 00` 래퍼**로 한 벌 더 있고, 이쪽이
실제 렌더 대상인데 추출기가 래퍼 때문에 레코드로 인식하지 못했다.

- 탐지: ISO 전수에서 `0F 00` 앞으로 NUL 까지 거슬러 `10` 으로 시작하고
  **미인덱스**인 레코드를 찾아, 내용(`raw_hex`)이 인덱스 레코드와
  **정확히 일치**할 때만 그 번역을 적용(fail-closed). 16건 매칭 → 슬롯에
  들어간 **8건 패치**(나머지는 한글이 슬롯 초과 — 짧춤 검토 대상).
- 래퍼 사본의 내용 용량은 원본 인덱스 레코드보다 **1B 여유**가 있다
  (`10`/`0F` 가 별도 바이트라서).

### 래퍼 변종 3종 (2026-08-30 전투 스테이트 실측 — b10 v11)

전투 세이브스테이트(`diag_battle*.State`) RAM 덤프로 렌더 소스를 확정한 뒤
래퍼 매처를 일반화했다. **24종 전량 패치**(16→22→24).

1. **접두 제어 바이트가 `10` 만이 아니다** — `0D`(줄바꿈 선행)도 있다.
   접두 1B 있음/없음을 모두 시도.
2. **끝 제어(`\p`=0C, `\n`=0D)가 래퍼의 `0F` 로 대체된 변종**이 있다
   (마법 시전 메시지). 인덱스 raw 와 맞출 때 끝 제어 3종을 함께 시도하고,
   한글 인코딩에서는 그 끝 제어를 떼고 `0F` 로 감싼다.
3. **다중 세그먼트 레코드**(`0F` 로 구분된 여러 문장)는 인덱스에 통째로
   없다 — 전투 결과 템플릿(`魔物を倒した`/`{%d}の経験値と`/
   `{%d}ギミルを手に入れた`/`{%s}を手に入れた`)이 여기 해당.
   `UNINDEXED_SEGMENTED` 로 세그먼트별 한글 조립 + 꼬리 00 패딩.
   통화명은 기존 대사 번역과 맞춰 **'기밀'** 사용.

**미인덱스 이름 전 사본 치환**(`UNINDEXED_NAMES`): 몬스터명 バルーン 은
포인터 재배치가 필요할 줄 알았으나 슬롯 6B 에 '벌룬'(5B)이 들어가
**35사본 제자리 치환**으로 끝났다.

### 전투 메시지 44종 = **인덱스에 아예 없음** (b10 v12)

`会心の一撃` 제보로 재조사한 결과, `0x8A51B~0x8AB0D` 의 전투 메시지
**44종 전체가 Z8 인덱스에 없다**(번역도 없음). 래퍼 사본과 달리 인덱스
대응 레코드가 없어 매칭으로는 못 살린다.

- 탐지 필터(고정밀): 미인덱스 + 미패치 + **서식 토큰(`%s`/`%d`) 포함** +
  SJIS 한자 포함 + 레코드 ≤60B. 느슨한 필터로는 코드·그래픽이 2,518건
  섞여 들어온다(실측) — 이 조합이 실무 기준.
- 번역은 이 세션에서 **신규 작성**하고 슬롯 적합을 전수 검증
  (`translation/b10_unindexed_battle.tsv`, 원문 바이트를 키로 전 사본 치환).
  용량 = 레코드 − 3B(접두·`0F`·NUL). **릴리스 전 인간 검토 대상**(§3).
- 실측: 45곳 치환, 빌드 잔존 일문 **0종**.
- 예: 会心の一撃→'의치명타!', 連続攻撃→'연속공격!!', 毒におかされた→
  '중독!', 攻撃をかわした→'공격회피!', 眠っている→'수면중'.

### 조사 제거 규칙 (2026-08-30 사용자 결정 — b10 v13)

**자리표시자 바로 뒤의 조사(은/는/이/가/의/을/를)는 전부 뺀다.**
한국어 조사는 앞 단어의 받침에 따라 달라지는데 `{%s}` 에 어떤 이름이
들어올지 런타임에 알 수 없어 "벌룬**는** 11피해" 같은 오류가 난다.
사용자 지시: "벌룬 11피해" 가 덜 어색하다.

- 적용 = 전투 TSV 3건 + 메뉴 오버라이드 7건 + 인덱스 번역 19종(오버라이드
  신규 추가). 번역 원본 CSV 는 건드리지 않는다.
- **자동 치환 함정 2건 (실측)**:
  ① `{%s}이쪽을주시!` 의 '이'는 조사가 아니라 **'이쪽'의 일부** — 위험
  후속 음절 집합(쪽/곳/것/때/런/문)을 제외 조건으로 둘 것. 해당 행은
  '{%s}노려본다!' 로 재작성.
  ② 조사를 빼면 **자리표시자가 인접**해 이름이 붙어버린다
  (`{%s}{%s}사용`) → 반칸 토큰 `{~}` 로 구분.
  ③ 레벨업 메시지 **후행 파라미터**(`{%s}{%s}{%s}…`)는 인접 자리표시자가
  아니라 원본 구조다 — `{~}` 삽입 금지.
- 부수 효과: 바이트가 줄어 NOFIT 142 → **139**.

### 같은 세션에서 잡은 파이프라인 버그

**제자리 루프가 `encoded()` 호출 전에 `same_as_original` 행을 먼저
걸러내고 있었다** → 오버라이드로 구제한 메모 헤더가 54사본 전부 일문으로
남았다. 두 곳의 규칙을 일치시켜 해소(헤더 정상 출력 확인).

## 2.15 b15 — 1바이트 한글 코드: 카타카나 디코더 테이블 치환 (2026-10-09 밤)

사용자: "축약하면 의미가 흐려진다. 원문(전체 표기)을 표시할 방법을 찾자." 길이 캡은
화면 폭이 아니라 **저장 바이트**(한글 1자 = 2B + NUL)이므로 폰트로는 해결이 안 된다.
대신 **엔진이 1바이트 가나를 2바이트 SJIS 로 바꾸는 디코더**를 이용했다.

### 실측 (ISO 정적 + 엔진 역어셈블)

```
$93A3  CMP #$A7 / BCC ret ; CMP #$DE / BCS ret      ; 1바이트 카타카나 $A7-$DD (55코드)
$93AB  SEC SBC #$A7 ; ASL ; TAX
$93B0  LDA $9104,X → $2FE0 (lead) ; LDA $9105,X → $2FDF (trail)   ← **[lead,trail] 테이블**
$93C0  CMP #$28 / CMP #$7B ; CLC ADC #$77 → trail, LDA #$82 → lead   ; 히라가나 $28-$7A (선형)
```

- 테이블(110B)은 **두 사본**: 엔진 `$9104` = ISO `0x86104`, 메뉴 모듈 `$83D0` = ISO
  `0x453D0`(디코더 사본 `0x455EE`, 저장처 `$3440/$3441`). 배틀 모듈에는 사본 없음
  (시그니처 전수 검색) — 배틀 이름 렌더가 이 테이블을 쓰는지는 **런타임 게이트**로 확인.
- 테이블 항목을 한글 음절의 **기존 2바이트 배정 SJIS** 로 바꾸면 코드 `$A7+i` 가 그 글리프를
  가리킨다. 새 글리프 불필요, 가나 글리프 무수정(2바이트 가나 폴백은 그대로 읽힘).
- 대가: 1바이트 **카타카나**로 남아 있는 미번역 일문은 엉뚱한 한글 음절로 보인다
  (히라가나 경로는 안 건드렸으므로 히라가나 폴백은 정상). → "일문 대신 뜻 없는 한글" =
  미번역 잔존 신호.
