# Z3 — 모듈 섹션과 확장 공간 규약

상태: **구조·identity·fail-closed 검증 PASS**  
실행일: 2026-07-18

## 참고 구조

천외마경 번역 프로젝트의 실제 빌드는 추출된 모듈별 binary를 WLA-HuC6280과
WLALINK로 따로 패치하고, 완성 모듈을 큰 중간 컨테이너에 배치한 뒤 필요한 단위로
다시 분리한다. 일부 캐시 모듈은 placeholder를 둔 첫 링크 후 완성된 결과를 넣는
두 번째 링크도 수행한다.

참고:

- https://github.com/suppertails66/tenmatools/blob/master/tenma/build.sh
- https://github.com/suppertails66/tenmatools/tree/master/tenma

이 프로젝트에서는 아직 추가 ASM이 없으므로 WLA object 대신 동등한 byte-section
계약을 먼저 구현했다. Z4에서 실제 HuC6280 코드가 추가되면 같은 section spec을
WLA-HuC6280 입력으로 교체할 수 있다.

## 섹션 모델

모든 모듈은 다음 다섯 section을 같은 순서로 가진다.

1. `original`: Z2에서 추출한 identity binary 전체, 고정·불변
2. `extension_code`: 모듈 전용 HuC6280 확장 코드
3. `text`: 해당 family가 소유하는 번역 문자열
4. `glyph`: 해당 family에서 필요한 Galmuri8x8 글리프
5. `relocation`: 포인터·분기·loader table 변경 기록

Z3에서는 `original`만 비어 있지 않다. 나머지 section은 모두 크기 0이며 placement가
`unallocated`다. 10개 실제 바이너리의 linked output은 입력과 SHA-256이 동일하다.
Memo와 초상화는 정확한 코드 진입 PC가 미확정이므로 virtual subrenderer spec으로만
등록하고 확장을 차단했다.

## 확장 등록 트랜잭션

비영 section은 다음 항목이 하나의 registry entry에 함께 등록돼야 한다.

- 소유 module과 family
- 물리 LBA와 sector capacity
- runtime physical bank
- 소유 loader의 table patch
- 해당 family에서만 실행되는 load condition
- family 종료 시 수명 종료 조건

sector allocation만 있거나 loader patch만 있는 상태는 허용하지 않는다. 현재
`extension_registry.json`은 `LOCKED_EMPTY_AT_Z3`이며 승인된 확장은 0개다.

## 명시적 금지 항목

- Work RAM에서 영속 코드 실행
- 0x00/0xFF fill run을 빈 공간으로 추정
- loader와 무관한 implicit gap 사용
- 모든 CD_READ 뒤 자동 sidecar 적재
- `$68-$7F` 장면 교체 bank를 공유 영속 저장소로 사용
- 다른 family의 code/text/glyph 주소 참조
- loader 등록 없는 신규 LBA 사용

장면 bank `$68-$7F`는 96섹터, 196,608바이트 전체가 전환마다 교체된다. 해당 영역의
section 수명은 반드시 `owning_family_only`여야 한다.

## 다음 단계

Z4에서는 `field.main_engine`과 필요한 field scene 소유권만 사용해 한 글자 `가`의
모듈 로컬 PoC를 만든다. 그때 최초의 non-zero registry entry를 추가하며, LBA/sector
allocation과 field loader registration을 같은 변경으로 제출해야 한다. Memo, 첫 전투,
필드 복귀, 탑 진입을 모두 통과하기 전에는 다른 family 확장을 승인하지 않는다.
